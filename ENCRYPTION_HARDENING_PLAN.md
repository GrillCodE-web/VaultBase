# План: полное шифрование локальной БД + E2E-синхронизация + кросс-платформенная сборка

> **СТАТУС РЕАЛИЗАЦИИ (2026-08-06): 🔄 ЧАСТИЧНО.**
> Готово: field-level AES-256-GCM, PBKDF2 600k, ключи зануляются при блокировке,
> авто-лок по неактивности, admin-пароль не пишется на диск. Не сделано: полное шифрование
> файла БД (SQLCipher), смена мастер-пароля через UI, E2E-шифрование sync-группы.
> Прогресс — в [CHECKLIST.md](./CHECKLIST.md).

**Проект:** VaultBase 2.5.0 (Tauri 2 + React + Rust + SQLite)
**Дата:** 2026-08-03
**Стадия:** разработка, пользователей нет, переделывается полностью
**Цель:** данные установленной программы невозможно расшифровать локально без
мастер-пароля; сервер не хранит ничего в открытом виде; сборка под Windows/Linux/macOS.

## 1. Аудит: что сейчас не защищено

### 1.1 База лежит открытым текстом

Шифруются только 14 полей через `encrypt_field()` (`database.rs:95`):
`credit_cards.card_number/cvv/holder_name`, `drops.recipient_name/address/phone`,
`email_pool.email`, пароли `imap_accounts`/`smtp_configs`, `config.license_token`.

**Читается любым DB Browser без пароля:**

| Таблица                                    | Что утекает                                                                  |
| ------------------------------------------ | ---------------------------------------------------------------------------- |
| `imap_messages`                            | темы, **тела писем**, отправители, получатели, трек-номера                   |
| `orders`                                   | номера заказов, статусы, суммы                                               |
| `credit_cards`                             | `bin`, `last4`, `bank_name`, `card_type`, `status`, **`notes`**, `card_hash` |
| `activity_log`                             | вся история действий                                                         |
| `shops`, `profiles`, `catalog_*`, `config` | домены, заметки, каталог, `installation_id`                                  |

### 1.2 Побочные каналы утечки

- **WAL/SHM** — `journal_mode = WAL` (`database.rs:64`) → `vaultbase.db-wal`
  и `-shm` рядом, открытым текстом.
- **Бэкапы** — `auto_backup()` (`main.rs:206`) делает `fs::copy` открытой базы,
  до 30 копий в `%LOCALAPPDATA%\vaultbase\backups`, новая при каждом unlock.
- **`bcrypt`-хеш пароля** в самой базе (`config.master_password_hash`) → мишень
  для офлайн-брутфорса.
- **KDF слабоват** — PBKDF2-SHA256 600k (`encryption.rs:34`) не memory-hard,
  хорошо параллелится на GPU.

### 1.3 Три бага, ломающих прод

**A. `panic!` в release.** `encryption.rs:108-130`: `hash_value()` требует env
`vaultbase_HMAC_SECRET`, иначе в release **паникует**. У установленной программы
переменной нет → краш на любой работе с footprints (`database.rs:3367-3386`).

**B. Несуществующая колонка.** `main.rs:417, 446, 488` читают
`SELECT card_hash, encrypted_data FROM credit_cards`, но колонки нет ни в схеме
(`database.rs:4652-4676`), ни в `ALTER TABLE` → `card_not_found` при каждой смене
статуса карты.

**C. Обход слоя Database.** `ws_sync.rs:324, 336, 348` открывают БД сырым
`Connection::open()` → после SQLCipher молча отвалятся.

### 1.4 Синхронизация: сервер видит слишком много

| Endpoint           | Payload                                                                                   | Проблема                                                      |
| ------------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `/sync/cards`      | `card_hash`, `status`, **`notes` открытым текстом**, `encrypted_data` (`sync.rs:472-478`) | заметки уходят в открытом виде                                |
| `/footprint`       | HMAC-хеши + **`bin` как есть** + `installation_id_hash` (`sync.rs:60-117`)                | BIN не хеширован; `installation_id_hash` склеивает всё в граф |
| `/footprint/check` | хеши + `shop_domain` (`sync.rs:221`)                                                      | видно, какие магазины проверяются                             |

**Главная проблема E2E — `group_key` генерирует сервер.** `sync.rs:348` и `sync.rs:394`:

```rust
let group_key = json["group_key"].as_str().ok_or("missing_group_key")?
```

Ключ приходит **от сервера** и просто складывается в `config.sync_group_key`.
Значит сервер знает групповой ключ → **E2E в текущей схеме невозможен в принципе**,
даже если начать шифровать payload этим ключом. Схему обмена ключами надо
переделывать (§4).

### 1.5 Платформенные пробелы

- **`tauri.conf.json:44`** — `"targets": ["dmg", "app"]` → **сборка только под macOS.**
  Windows (`msi`/`nsis`) и Linux (`deb`/`appimage`) не собираются вообще.
- CI отсутствует (`.github/workflows/` нет) → нет матричной сборки.
- `signingIdentity: "-"` — ad-hoc подпись, без нотаризации.
- `set_dock_badge` только под macOS (`main.rs:2054-2080`), на Windows/Linux заглушка.
- `db_path()` (`main.rs:43-65`) через `dirs::data_local_dir()` — корректно
  кросс-платформенно, **оставляем**.

## 2. Локальное шифрование

### 2.1 Иерархия ключей

```
мастер-пароль (только в голове пользователя)
      │
      ▼  Argon2id (m=256MiB, t=3, p=4, соль 32 байта OsRng)
     KEK  (32 байта, RAM, ZeroizeOnDrop)
      │
      ▼  AES-256-GCM decrypt
     DEK  (32 байта OsRng, RAM, ZeroizeOnDrop)
      │
      ├─► SQLCipher: PRAGMA key   → вся БД + WAL
      ├─► HKDF(info="footprint-hmac-v1")  → HMAC-секрет (заменяет env-переменную)
      └─► HKDF(info="backup-v1")          → ключ шифрования бэкапов
```

**На диске только:** соль KDF, `dek_wrapped` = AES-GCM(KEK, DEK), параметры KDF.
Самого ключа нет нигде. Проверка пароля = успешное разворачивание DEK
(GCM-тег не сойдётся при неверном) → **`bcrypt`-хеш удаляется из базы**,
офлайн-мишени не остаётся.

**Argon2id вместо PBKDF2:** PBKDF2 хорошо ускоряется на GPU. Argon2id с `m=256MiB`
требует 256 МБ **на каждую параллельную попытку** — обнуляет преимущество GPU/ASIC.
Цена ~0.4-0.8 с на разблокировку, приемлемо для однократного ввода.

**Зависимости** (`Cargo.toml`):

```toml
rusqlite = { version = "0.31", features = ["bundled-sqlcipher-vendored-openssl"] }
argon2   = "0.5"
hkdf     = "0.12"
# убрать: bcrypt
```

`bundled-sqlcipher-vendored-openssl` — единственный вариант с одинаковым поведением
на трёх ОС без установки SQLCipher в систему. **Тянет vendored OpenSSL → NASM+Perl
обязательны для Windows-сборки** (Perl есть, NASM надо поставить).
Проверить `cargo tree -d`: `r2d2_sqlite` 0.24 должен использовать ту же
`libsqlite3-sys`, иначе в бинарнике окажется два разных SQLite.

### 2.2 Хранение метаданных ключа — `keyring.json`

Соль и `dek_wrapped` нельзя держать в самой БД (она зашифрована этим же DEK —
циклическая зависимость). Отдельный файл рядом с БД:

```json
{
  "version": 1,
  "kdf": { "algo": "argon2id", "m_cost_kib": 262144, "t_cost": 3, "p_cost": 4 },
  "kdf_salt": "<base64, 32 байта>",
  "dek_wrapped": "<base64: nonce[12] || ct || tag[16]>",
  "cipher": "aes-256-gcm"
}
```

Файл не секретный (без пароля бесполезен), но **обязателен** для открытия БД →
включается в бэкап, отсутствие проверяется при старте с внятной ошибкой.

### 2.3 Новый модуль `keyring.rs`

```
pub struct KeyMaterial { dek: [u8;32] }   // ZeroizeOnDrop

create(password)              -> KeyMaterial   // генерит соль+DEK, пишет keyring.json
unlock(password)              -> Result<KeyMaterial>
change_password(old, new)     -> ()            // перезаворачивает ТОТ ЖЕ DEK
derive_subkey(info: &[u8])    -> [u8;32]       // HKDF для HMAC/бэкапов
```

**Смена пароля больше не перешифровывает данные** — меняется только обёртка DEK.
Это убирает рискованный `reencrypt_all()` (`main.rs:286`), где краш посередине
оставлял базу неконсистентной.

### 2.4 Открытие БД

`database.rs:40` — `Database::open()` принимает `&KeyMaterial`, **первым запросом**
после `Connection::open`:

```sql
PRAGMA key = "x'<hex DEK>'";
PRAGMA cipher_memory_security = ON;
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
```

**То же самое в `with_init` пула** (`database.rs:59-70`) — иначе соединения из пула
не прочитают базу. Проверка: `SELECT count(*) FROM sqlite_master`.

### 2.5 Упрощение модели блокировки

- удалить `config.master_password_hash` и всю `bcrypt`-логику
  (`main.rs:132, 159, 267, 277`), включая апгрейд cost factor (`main.rs:163-174`) —
  целиком, legacy не поддерживаем;
- удалить `config.encryption_salt` (переезжает в `keyring.json`);
- `is_password_set()` → проверка существования `keyring.json`;
- **сохранить** rate-limit (`rate_limiter::Strict`) на `unlock` — от подбора через UI;
- **сохранить** field-level шифрование поверх SQLCipher для `card_number`, `cvv`,
  паролей IMAP/SMTP. Двойной слой защищает от дампа памяти, где открытая БД
  уже отдаёт остальные поля.

### 2.6 Старая дев-БД

Кода миграции **нет**. Один раз вручную:

```
mv vaultbase.db     vaultbase.db.old
mv vaultbase.db-wal vaultbase.db-wal.old
mv vaultbase.db-shm vaultbase.db-shm.old
```

Новая база создаётся чистой и сразу зашифрованной. `.old` остаётся открытым текстом
— решить позже, нужно ли что-то оттуда достать (каталог 3542+3470 строк
переимпортируется штатной `import_catalog_*`).

**Windows:** `fs::rename` упадёт с `Access denied`, пока открыт хендл → сначала
`drop(pool)`, `drop(conn)`.

### 2.7 Автолок с затиранием ключа

Сейчас `autolock_timeout` есть (`database.rs:30`), `lock()` делает
`clear_encryption()` (`main.rs:236`) — то есть просто `encryption = None`.
Нужно:

- `KeyMaterial` с `ZeroizeOnDrop` → DEK реально затирается, а не просто теряет ссылку;
- закрывать пул и соединения (иначе SQLCipher держит расшифрованные страницы в кеше);
- фоновой поток, проверяющий `last_activity` (`database.rs:29`);
- после автолока UI показывает экран разблокировки; фоновые потоки (IMAP-поллинг
  `main.rs:1460`, tracking `main.rs:1549`) должны корректно пропускать тики
  в залоченном состоянии — сейчас проверка `is_locked()` есть (`main.rs:1463`),
  подтвердить, что её достаточно.

### 2.8 Бэкапы

`main.rs:206-231` — сейчас `fs::copy` открытой базы. Меняем:

- копия шифрованной БД зашифрована сама → копируем как есть, но **после**
  `PRAGMA wal_checkpoint(TRUNCATE)`;
- рядом кладём копию `keyring.json` — без неё бэкап не открыть;
- `import_backup` (`main.rs:1228`) — учесть бэкап от другой установки (свой keyring);
- удалить все старые открытые бэкапы при первом запуске новой версии.

### 2.9 Фикс трёх багов (делаем ПЕРЕД шифрованием)

Порядок сознательный: одновременно с SQLCipher непонятно, что именно сломалось.

- **A:** `hash_value()` → метод, берущий секрет из `derive_subkey(b"footprint-hmac-v1")`.
  Уникален на установку, недоступен без пароля, не требует настройки. Убрать
  `panic!` и env-переменную. Затронуто: `database.rs:165, 3367, 3373, 3383, 3386`.
- **B:** `ALTER TABLE credit_cards ADD COLUMN encrypted_data TEXT;` — **или** решить,
  что поле лишнее, и убрать из `CardSyncUpdate` (§6.1).
- **C:** `ws_sync.rs:324, 336, 348` — перевести на общий доступ через `STATE.db`.

## 4. E2E-шифрование групповой синхронизации

### 4.1 Проблема

`sync.rs:348, 394` — `group_key` приходит **от сервера**. Сервер знает ключ →
любое шифрование этим ключом бессмысленно. Нужна новая схема, где ключ **никогда
не покидает клиентов**.

### 4.2 Целевая схема

```
Создатель группы:
  генерит group_key (32 байта OsRng) ЛОКАЛЬНО
  сервер получает только group_id — ключа не видит никогда

Присоединение (pair-code):
  pair-code играет роль одноразового секрета
  group_key передаётся зашифрованным на ключе, производном от pair-code:
     wrap_key = Argon2id(pair_code, salt=group_id)
     сервер хранит только AES-GCM(wrap_key, group_key) и отдаёт присоединяющемуся
  сервер не знает pair-code в открытом виде (хранит хеш) → развернуть не может

Синхронизация карт:
  payload = AES-256-GCM(group_key, JSON{ card fields, notes, status })
  на сервер уходит: card_hash (для дедупа) + blob. Больше ничего
```

**Оговорка про pair-code:** его стойкость = стойкость всей схемы. Короткий код
(6 символов) подбирается. Нужен либо длинный код (≥20 символов base32), либо
жёсткий rate-limit и короткий TTL на сервере. **Требует изменений на сервере.**

### 4.3 Что меняется

- `sync.rs` — `create_group`, `join_group` (§`sync.rs:334-400`), `push_card_updates`;
- `ws_sync.rs` — `apply_card_updates` расшифровывает блоб;
- `config.sync_group_key` — хранится в уже зашифрованной БД, дополнительно
  под field-encryption;
- **серверная часть** — вне этого репозитория, нужны правки эндпоинтов
  `/sync/group/create`, `/pair`, `/join`, `/sync/cards`.

### 4.4 Ограничение

E2E защищает **содержимое**. Метаданные (кто, когда, сколько карт, `card_hash`
для дедупа) сервер всё равно видит. Полностью скрыть их без серьёзного усложнения
(padding, фиктивный трафик) невозможно.

## 5. Кросс-платформенность

### 5.1 `tauri.conf.json`

`"targets": ["msi", "nsis", "deb", "appimage", "dmg", "app"]` (или `"all"`),
добавить секции `bundle.windows` и `bundle.linux`.

### 5.2 CI — матричная сборка (`.github/workflows/build.yml`)

| Раннер           | Цель              | Доустановить                                                                                                             |
| ---------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `windows-latest` | `msi`, `nsis`     | MSVC Build Tools, **NASM**, Perl                                                                                         |
| `ubuntu-22.04`   | `deb`, `appimage` | `libwebkit2gtk-4.1-dev`, `libssl-dev`, `build-essential`, `libgtk-3-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev` |
| `macos-latest`   | `dmg`, `app`      | Xcode CLT                                                                                                                |

**Самое хрупкое:** `bundled-sqlcipher-vendored-openssl` компилирует OpenSSL из
исходников на каждом раннере. Проверять первым делом.

### 5.3 Платформенные детали

- **Windows:** файл не переименовать при открытом хендле; Defender может блокировать
  неподписанный свежий `.exe`.
- **Linux:** `dirs::data_local_dir()` → `~/.local/share/vaultbase`. Выставить
  права `0700` на папку с БД и `keyring.json` — umask может дать `0755`
  (на Windows/macOS права наследуются от профиля).
- **macOS:** `signingIdentity: "-"` → Gatekeeper ругается; для распространения
  нужна Developer ID подпись + нотаризация.
- **Updater** (`tauri.conf.json:58-62`) — артефакты для всех целей, сейчас настроен
  под macOS.

### 5.4 Тестовая матрица (на каждой ОС)

Чистая установка → создание пароля → внесение данных → перезапуск → разблокировка;
неверный пароль; автолок по таймауту; смена пароля; бэкап + восстановление;
**попытка открыть БД внешним инструментом — должна провалиться**.

## 7. Риски

| Риск                                      | Вероятн.    | Митигация                                                                           |
| ----------------------------------------- | ----------- | ----------------------------------------------------------------------------------- |
| vendored OpenSSL не собирается (Windows)  | **высокая** | Проверить первым делом в Этапе 2. Fallback: `bundled-sqlcipher` + системный OpenSSL |
| Конфликт версий `libsqlite3-sys`          | средняя     | `cargo tree -d`                                                                     |
| Забытый пароль = потеря данных            | высокая     | Осознанно. Усилить предупреждение в UI                                              |
| Потеря `keyring.json` = потеря данных     | средняя     | В бэкап; проверка при старте с внятной ошибкой                                      |
| E2E требует правок сервера                | **высокая** | Этап 4 блокируется; спланировать серверную часть отдельно                           |
| Слабый pair-code ломает E2E               | высокая     | Длинный код + rate-limit + короткий TTL                                             |
| Argon2id 256 МБ тормозит на слабой машине | низкая      | Параметры в `keyring.json`, можно снизить                                           |
| Автолок не чистит кеш SQLCipher           | средняя     | Закрывать пул и соединения, не только `encryption = None`                           |

## 10. Итог

**Даёт:** файл БД, WAL и бэкапы нечитаемы без пароля на всех трёх ОС; ключа нет
на диске; офлайн-брутфорс упирается в Argon2id 256 МБ; нет bcrypt-мишени в базе;

в RAM); защиты от кейлоггера; сокрытия адреса сервера (виден в трафике и памяти);
сокрытия метаданных синхронизации (кто/когда/сколько).
