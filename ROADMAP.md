## Фаза 2 — Раздел «Курьеры / Посылки» (Stuffer) ✅ (готово, v2.5.0)

Реализовано (backend + UI, проксирование Stuffer API в реальном времени):

- [x] Rust-модуль `src-tauri/src/stuffer.rs` — HTTP-клиент (ureq), serde-структуры,
      обработка HTTP-кодов и `{"error":...}`, таймаут 15с.
- [x] 8 Tauri-команд: `stuffer_get_config`, `stuffer_set_config`,
      `stuffer_list_couriers`, `stuffer_list_available_couriers`, `stuffer_add_courier`,
      `stuffer_list_packages`, `stuffer_get_labels`, `stuffer_create_package`.
- [x] Права: `view_couriers`, `manage_couriers`, `view_packages`, `create_packages`
      (`models.rs`); просмотр/создание — операторам по умолчанию, добавление курьеров —
      admin/по праву.
- [x] UI: раздел «Курьеры / Посылки» в навигации — вкладки Мои курьеры / Доступные /
      Посылки, добавление курьера, таблица посылок, просмотр и скачивание лейблов
      (base64 → PDF), форма создания посылки с трек-номерами (`src/pages/Couriers.jsx`).
- [x] Настройка Stuffer API в Настройках (base URL + маскированный ключ);
      ключ хранится в `config` как секрет, во фронт не отдаётся (только флаг `api_key_set`).
- [x] i18n EN/RU (~60 ключей), стили `styles/pages/couriers-redesign.css`.

Проверено: `cargo check` ✅, `npm run lint` ✅, `vite build` ✅, `vitest` 317/317 ✅.

Осталось (по мере необходимости):

- [x] Read-only методы проверены на реальном Stuffer API (couriers/available/packages) ✅
- [ ] Живой прогон пишущих методов (`add_courier`, `new_package`) с реальной мутацией.
- [ ] Опциональная привязка курьера к профилю и посылки к локальному заказу
      (см. обоснование в [DESIGN_MACOS_PLAN.md](DESIGN_MACOS_PLAN.md) §13).
- [ ] Кэш курьеров/посылок в БД (сейчас — проксирование в реальном времени).
- [ ] Раздел PPTP API (по аналогии со Stuffer) — ждём документацию.
