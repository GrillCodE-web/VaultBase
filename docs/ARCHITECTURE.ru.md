## Доступ и вход

```
┌────────────┐   activation key   ┌──────────────┐   мастер-пароль    ┌──────────────┐
│  Активация │ ─────────────────► │  Мастер-ключ │ ─────────────────► │   Автовход   │
│  лицензии  │  (роль с сервера)  │ разблок. БД  │  выводит AES-ключ  │ (соло-режим) │
└────────────┘                    └──────────────┘                    └──────────────┘
      │                                                                       │
      └── config license_role (admin/operator), обновляется на каждом /verify ─┘
```

- **Роль** несёт лицензия (на стороне сервера), применяется на клиенте при activate/verify.
  В соло-режиме (один локальный пользователь) экрана логина нет — вход сразу после
  мастер-пароля.
- Детали: [AUTH_AND_ROLES.md](AUTH_AND_ROLES.md).

## Производительность

### Виртуализация

- `@tanstack/react-virtual` для всех больших списков
- Cards, Orders, Profiles, Emails виртуализированы
- Обычно 10–20 DOM-узлов вне зависимости от объёма данных

### Кэширование

| Слой          | Длительность | Инвалидация    |
| ------------- | ------------ | -------------- |
| Zustand store | 5 минут      | Ручной refresh |
| SQLite        | Постоянно    | При записи     |
| BIN-кэш       | 24 часа      | По TTL         |

### Оптимизация БД

- Пул соединений (r2d2, 4 конкурентных)
- Режим WAL для конкурентного чтения
- Составные индексы на часто запрашиваемых колонках
- Оптимизация запросов (JOIN вместо N+1)
