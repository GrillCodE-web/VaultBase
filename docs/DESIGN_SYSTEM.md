## 2. Каскад: слои, порядок, Tailwind

`src/styles/index.css` объявляет порядок слоёв:

```css
@layer tw-base, app, tw-utils;
```

Порядок импорта в `index.css` (это критично, см. §16):

1. `fonts.css` — **вне слоёв** (`@font-face` в слое невалиден).
2. `tokens.css` — **вне слоёв**: `:root` и keyframes должны быть максимально сильными/доступными везде.
3. `base.css` → `layout.css` → `components.css` → `pages.css` — все в `@layer app`, в этом порядке.
4. Tailwind 4: `@import 'tailwindcss' theme(...) layer(tw-base)` и `utilities layer(tw-utils)`.

### Что это значит на практике

- **Кто кого перебивает:** `tw-utils` > `app` > `tw-base`. Класс-утилита Tailwind
  (`class="text-accent"`) перебьет стиль нашего класса из `components.css`.
  Неслоёвые стили (tokens/base-хвост) перебивают любые слоёвые при равной
  специфичности — это используется осознанно.
- **Внутри `app`** порядок файлов решает конфликты: `pages.css` перебивает
  `components.css` при равной специфичности. Поэтому страничные классы могут
  докручивать компонентные.
- **Tailwind без конфига:** `tailwind.config.js` нет и не нужен — Tailwind 4
  настраивается через `@theme` прямо в `index.css`. Туда замаплены цвета:
  `accent, accent-fg, accent-dim, bg, surface, card, card-hi, inset, border,
border-hi, separator, text, text-2, text-3, muted, green-t, red-t, yellow-t,
blue-t, orange-t` → соответствующие CSS-переменные. Т.е. `text-text-2`,
  `bg-card`, `border-border` в JSX берут значения из наших токенов.
- **Двойной набор утилит:** рукописные утилиты (≈2000 строк в начале
  `components.css`, исторически вытащены из инлайн-стилей) + Tailwind-утилиты.
  При редизайне не плодить третий набор.

## 3. Токены (`tokens.css`)

Все токены объявлены в `:root` (светлая тема — база), переопределены в
`[data-theme='dark']` и продублированы для `[data-theme='system']` внутри
`@media (prefers-color-scheme: dark)`. **Правило: любой новый токен объявляется
в трёх местах** (`:root`, `dark`, system-dark), иначе в одной из тем получим
фантом и молча сломанный цвет. `[data-theme='light']` существует только чтобы
перебить системный тёмный режим (значения = `:root`).

**Масштаб:** 169 уникальных токенов, 397 деклараций (`:root` 168, dark 114,
system-dark 89, light 0 — см. ниже). Сводный дамп всех значений по темам:
§3.9.

### 3.1 Типографика

| Токен                                                                                       | Значение                        | Назначение                                                                   |
| ------------------------------------------------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------- |
| `--font-ui`                                                                                 | `'Geist', -apple-system, …`     | Весь UI. Системные имена — fallback до swap шрифта.                          |
| `--font-mono`                                                                               | `'Geist Mono', ui-monospace, …` | **Все числовые поля**: табличные цифры (`tabular-nums`) выравнивают колонки. |
| `--fs-title` / `--fs-heading` / `--fs-body` / `--fs-control` / `--fs-caption` / `--fs-mono` | 20 / 15 / 13 / 13 / 11 / 12 px  | Вся шкала размеров текста.                                                   |
| `--lh-title` / `--lh-heading` / `--lh-body` / `--lh-caption`                                | 24 / 20 / 18 / 14 px            | Межстрочные интервалы.                                                       |

Заголовки `h1..h6` жёстко привязаны к шкале в `base.css` (h2=17px и h4=14px —
единственные «внешкальные» значения, зашиты прямо в base).

### 3.3 Слои поверхностей

Светлая: `--bg #ececec` → `--surface #f5f5f7` → `--card #ffffff` →
`--card-hi #f9f9fb`, углубление `--inset #f0f0f2`.
Тёмная: `--bg #0c0d10` → `--surface #131519` → `--card #16181d` →
`--card-hi #1c1f26`, `--inset #0e0f13`.

Ступени светлоты нарочно малы — панели различаются слоями, **без тяжёлых теней**.
При редизайне сохранять «ступенчатость» (каждый следующий слой светлее), иначе
интерфейс схлопнется в одно пятно.

### 3.4 Границы, текст, интерактив

- Границы: `--border` (10% чёрного / 9% белого), `--border-hi` (16%), `--separator` (6%), `--border-accent`.
- Текст: `--text` → `--text-2` (62–64%) → `--text-3`/`--muted` (40–42%) → `--dim` (26–28%). Четыре ступени, не больше.
- Интерактив: `--hover` (5–6%), `--hover-row` (3–4%), `--active-press` (9–11%), `--focus-ring: 0 0 0 3px rgba(10,132,255,.5)` (кольцо всегда **синее**, не акцентное — как в macOS).

- Роли: `--role-admin-bg/color`, `--role-user-bg/color`.

### 3.9 Полнота тем и «дыра» в system (важно при редизайне)

`[data-theme='light']` намеренно содержит **только** `color-scheme: light`
(`tokens.css:424–426`) — все значения берутся из `:root`. Это правильно.

**Но обнаружен реальный рассинхрон:** в `[data-theme='dark']` переопределено
**114** токенов, а в `@media (prefers-color-scheme: dark) [data-theme='system']` —
только **89**. 23 токена имеют dark-значение, но **отсутствуют в system-блоке**;
(`--purple-t` при этом есть в обоих, `#d17ff5`). Это значит: у пользователя с
`data-theme='system'` и тёмной ОС
эти токены **молча откатываются к СВЕТЛЫМ значениям из `:root`**, и элемент
«выпадает» из тёмной темы.

Разработчики это частично знали: в `tokens.css:543–576` есть «дописка» с
комментарием «Токены, которые есть в dark, но отсутствовали здесь — без них
system-тёмная брала светлые из :root». Но дописка **неполная**. Токены, у
которых dark ≠ root и которые **всё ещё отсутствуют в system-блоке** (реально
используются в CSS — 13 шт.):

`--purple-bright` (root `#9f3fd0` / dark `#d17ff5`), `--glass-bg`,
`--glass-border`, `--sidebar-bg`, `--sidebar-border`, `--shadow-xs/sm/md/lg/window`,
`--hover`, `--hover-row`, `--active-press`, `--overlay-backdrop`, `--overlay-modal`,
`--overlay-loading`, `--neutral-border`, `--teal-dim`, `--teal-border`,
`--indigo-dim`, `--purple-alt-dim`, `--role-admin-bg`, `--role-user-bg`.

**Вывод для редизайна:** это либо дочинить (дописать недостающие 23 в
system-блок), либо — чище — перейти на схему, где system не дублирует значения,
а JS один раз резолвит `system → light|dark` и ставит конкретный `data-theme`
(тогда блока system вообще не будет и рассинхрон исчезнет как класс бага).
Текущая схема «дублируем руками» уже один раз дала этот баг и даст снова.
Полный машинный дамп можно пересоздать парсером по `tokens.css` (регулярка
`--name: value` с отслеживанием текущего theme-блока), сверять при изменениях.

- Оверлеи: `--overlay-dark .28` → `--overlay-darker .4` → `--overlay-modal .65`,
  `--overlay-backdrop .25`, `--overlay-loading .8` (в тёмной теме темнее).

### 3.6 Отступы, радиусы, тени, стекло, переходы

- **Отступы — 4px сетка:** `--sp-1…--sp-10` = 4/8/12/16/20/24/32/40px.
  Любые «магические» 10px/14px в новых стилях — нарушение сетки.
- **Радиусы — «аппаратные», резкие:** `--r-xs 2` / `--r-sm 3` / `--r-md 4` /
  `--r-lg 6` / `--r-xl 8` / `--r-2xl 10` / `--r-window 8` / `--r-full 9999`.
  Крупные радиусы (>10px) ломают характер дизайна.
- **Тени — глубина + фирменный 0.5px контур Retina:** `--shadow-xs` (только
  контур), `--shadow-sm/md/lg/window`. В тёмной теме контур 50% чёрный.
- **Стекло:** `--glass-bg`, `--glass-border`, `--glass-blur: 24px`,
  `--sidebar-bg`, `--sidebar-border` — для сайдбара и float-окна под вибрэнси.
- **Переходы — только цвет/прозрачность:** `--t-fast 100ms`, `--t-mid 120ms`,
  `--t-slow 180ms`, все `ease-out`. Трансформ-анимации в UI почти не используются
  (исключения — вход страницы и сайд-панель, см. keyframes).

## 4. Темизация

- **JS-сторона:** `src/hooks/useTheme.jsx`. Модульный стор на
  `useSyncExternalStore`, без провайдера. Режимы: `'system' | 'light' | 'dark'`,
  localStorage-ключ **`theme`**, дефолт — **`dark`**.
- **Атрибут:** `document.documentElement[data-theme]`, ставится **при загрузке
  модуля, до первого рендера** — иначе мигала бы светлая тема (`:root` светлый).
  Не переносить это в `useEffect`.
- **`system`** раскрашивается целиком на CSS-стороне через
  `@media (prefers-color-scheme: dark) { [data-theme='system'] { … } }` в
  `tokens.css:436`. JS слушает `matchMedia` только для иконки переключателя.
  Дублирование значений тёмной темы в system-блоке неизбежно (CSS не умеет
  присваивать наборы переменных по условию) — **держать оба блока синхронными**.
- `color-scheme: light dark` на `:root` — нативные контролы (скроллбары,
  формы) следуют теме. Убирать нельзя.
- Переключатели: кнопка в сайдбаре (`toggleTheme`: dark↔light) и выбор в
  Настройках (`cycleTheme`: system→light→dark). Оба ходят в один стор —
  двух источников истины больше нет (был баг с ключом `cc_theme`, не воскрешать).

## 5. «Атмосфера» тёмной темы (`base.css:317–365`)

Декоративные `body::before` (два радиальных cyan-свечения сверху) и
`body::after` (SVG-шум `feTurbulence`, opacity 0.028) — **только тёмная тема**
(+ дубль для system-dark). `pointer-events: none`, `z-index: 0`, контент
приподнят `#root { position: relative; z-index: 1 }`. Шум инлайнится data:URI —
CSP внешние запросы запрещает. При редизайне тёмной темы это первое место,
задающее «настроение»; в светлой теме атмосферы нет осознанно.

## 6. Шрифты (`fonts.css`)

- **Geist** (UI): woff2 Regular 400 / Medium 500 / SemiBold 600 / Bold 700.
- **Geist Mono** (цифры/код): woff2 Regular 400 / Medium 500.
- Файлы: `public/fonts/*.woff2`, по ~40 КБ каждый, итого ~242 КБ.
- `font-display: swap` + системные fallback-стеки в `--font-ui/--font-mono` —
  текст виден до загрузки шрифта.
- **CSP запрещает внешние шрифты** — только self-hosted. CSP задан в
  `src-tauri/tauri.conf.json:48` (`default-src 'self'…`, font-src 'self'),
  **не** meta-тегом (в `index.html`/`float.html` CSP-меты нет). Не подключать
  Google Fonts и прочие CDN: не сработает и не должно.
- `.mono, code, pre, [data-numeric]` → `--font-mono` + `tabular-nums`
  (`base.css`) — суммы/треки/номера не «прыгают» при обновлении.

### 7.2 Каркас (главное окно)

```
#root (100vh, overflow:hidden, z-index:1)
└─ .app-container (flex, 100vh, border-radius: --r-window)     components.css:2033
   ├─ .sidebar (48px → 200px .expanded, transition 180ms)      layout.css:12
   └─ .main-content-wrapper (flex column, overflow hidden)     components.css:2094
      ├─ .topbar (52px)                                        layout.css:344
      └─ .main-content-scroll (flex:1, overflow-y:auto,
         padding: 24px 28px → 16px при ≤900px)                 components.css:2104
         └─ .content (max-width: 1600px, margin: 0 auto)       layout.css:622
```

- **Отступы страниц задаёт обёртка один раз** (`24px 28px`) — страницам свои
  padding'и задавать нельзя (исторический бардак «где-то есть, где-то нет»
  закрыт именно здесь, см. комментарий в `components.css:2107`).
- **`.main-content-fill`** (`components.css:2124`) — вариант для страниц-
  «приложений» (IMAP): без padding, без скролла обёртки, внутренние панели
  скроллятся сами. Ему нужен `.page-enter { height: 100% }` рядом.
- **`.content` max-width 1600px + auto-margin** — вот и вся «автоподгонка»:
  контент центрируется и тянется до 1600px, дальше не расползается на широких
  мониторах. Там же задекларировано `animation: fadeIn 0.18s`
  (`layout.css:628`) — **но `@keyframes fadeIn` не определён нигде**:
  анимация фактически мёртвая (вероятно, имелся в виду `page-in` из
  `tokens.css:625`). Браузер молча игнорирует; «починить» = вернуть анимацию,
  которой давно не было, — это изменение поведения, решать осознанно.
- Сайдбар: свёрнут 48px (иконки + тултипы `.sbi-tip`), развёрнут 200px
  (`.sbi-label` появляется). Стекло: `backdrop-filter: blur(24px) saturate(180%)`;
  при реальной системной вибрэнси Rust ставит `[data-vibrancy='on']` и фон
  убирается (`layout.css:63`). Верхний padding 28px — под overlay-titlebar macOS.

## 12. Доступность (a11y)

- **Focus-visible:** единое кольцо `var(--focus-ring)` на всех интерактивах
  (`base.css:252` + каждый компонент). Старое правило с `border-radius: 4px` на
  `:focus-visible` **удалено намертво** — оно перебивало радиусы круглых кнопок.
- **`.sr-only`** (`base.css`), skip-ссылка `.skip-to-content`.
- **`prefers-reduced-motion`**: глушит все анимации, **кроме `.spinner`** —
  бесконечный индикатор загрузки обязан крутиться, иначе выглядит зависшим.
  Более широкий бан был откачен (регресс 2026-08), не возвращать.
- **`prefers-contrast: high`** (`layout.css:797`): усиление бордеров/текста.
- **Тач:** `pointer: coarse` — мишени 44px (`layout.css:706`, таблицы `4009`).
- **Формы статусов** не только цветом (§8.5) — требование WCAG 1.4.1.
- Контрастные пары `-t`-токенов подобраны под AA (пометки UX-001/007 в коде).

## 16. «Не трогать» — и почему

Каждый пункт подтверждён багом или намеренным компромиссом в коде:

1. **Порядок импортов и `@layer` в `styles/index.css`.** Перестановка меняет,
   какой слой кого перебивает, по всему приложению сразу.
2. **`tokens.css` и `fonts.css` вне слоёв** — осознанно: `:root` сильнее слоёв,
   `@font-face` в слое невалиден. «Причесать» их в `@layer` сломает темы/шрифты.
3. **`.page-enter { animation-fill-mode: both }`** (`tokens.css:717`) —
   без `both` fixed-элементы (модалки) прыгают во время анимации входа.
   Дубликаты правила в pages.css удалены, это единственное место.
4. **`--modal-size` инлайнится из `Modal.jsx`** (§8.4) — не хардкодить ширину.
5. **Keyframes — полный инвентарь (10 штук), дублей быть не должно:**
   `tokens.css`: `spin` (618), `page-in` (625), `skeleton-shimmer` (637),
   `toast-progress` (647), `btn-warn-shake` (657), `side-panel-in` (677),
   `row-flash` (689); `components.css:4819`: `slideDown`; `pages.css`:
   `progressLinear` (768), `shimmer` (2874). Раньше было 5 дублей `spin` по
   файлам — конфликтовали при reduced-motion, поэтому повторно объявлять
   существующие keyframes в других файлах нельзя. `!important` стоит только на
   `spin` внутри reduced-motion-исключения спиннера (`tokens.css:599`).
   Отдельно: `fadeIn` используется (`layout.css:628`), но нигде не определён
   (§7.2) — аудит это не ловит.
6. **Исключение `.spinner` из `prefers-reduced-motion`** (§12) — UX-регресс,
   откаченный 2026-08.
7. **Z-index сайдбара 50 (`--z-sticky`)** — у сайдбара `backdrop-filter`
   (свой stacking context); менять порядок наложения с модалками/тултипами
   можно только всей шкалой z-index целиком.
8. **Меню (`--z-menu 120`) выше модалок (100)** — BUG-019: меню «…» открывается
   из модалки. Не «чинить» это несоответствие.
9. **Хук скроллбара `background-clip: content-box`** (`base.css:199–244`) —
   прозрачная рамка + clip дают «плавающий» ползунок с отступом, тёмная и
   system-темы имеют свои варианты ползунка. Не упрощать до одного правила.
10. **`user-select: none` на `body` + `text` на текстовых элементах** —
    desktop-приложение не должно выделяться как веб-страница (сплошной
    синий шум при drag). Не глушить глобально наоборот.
11. **`[data-theme='system']`-блоки дублируют тёмную тему** (§4) — это не
    мусор, а механизм. Удаление дубля = белая вспышка/светлая тема у части
    пользователей.
12. **Отступ `.main-content-scroll { padding: 24px 28px }`** — единая точка
    отступов всех страниц (§7.2). Не добавлять страницам собственные padding.
13. **`data-vibrancy` флаги** ставит Rust-код, когда ОС реально дала вибрэнси;
    полупрозрачные фоны без этого флага = мыльное нечитаемое окно.
14. **Маркеры `источник: …`** в шапках секций — история консолидации v2.8.0,
    не удалять (трассировка происхождения классов).
15. **Лимиты файлов:** если файл вырастает (>~3000 строк у pages.css,
    > ~5000 у components.css) — новая функциональность идёт в новую секцию
    > внутри того же файла, новые CSS-файлы не плодим (кроме случая уровня
    > manager-app).

## 17. Manager-app — отдельная мини-система

`manager-app/` — самостоятельное Tauri-приложение (свой `package.json`,
свой `src-tauri`). Стили: **один файл `src/styles/manager.css` (622 строки)**,
без Tailwind, без слоёв. Свои токены в `:root` (только тёмная тема):
`--accent #4f8cff` (синий, не cyan), шрифт **Inter** (системный стек,
без self-hosted файлов), радиусы 10/7px, тени обычные (без 0.5px-контура).
Пересечений с основной системой нет: классы не импортируются туда-обратно.
Редизайн основного приложения manager-app не затрагивает и наоборот;
документация по его бэкенду — `docs/MANAGER_APP.md`.

## 18. Плейбук полного редизайна

Порядок, при котором риск минимален:

1. **Снять «до»:** `npm run dev` + `node scripts/visual-audit.mjs` → базовые
   скриншоты в `audit-shots/`.
2. **Перекраска = только `tokens.css`.** 90% редизайна — это замена значений
   в `:root` и `[data-theme='dark']` (+ дубль system). Сначала проверить §13
   (хардкод) — эти места не перекрасятся сами.
3. **Смена шрифта:** положить woff2 в `public/fonts/`, править только
   `fonts.css` + `--font-ui/--font-mono`. Внешние CDN запрещены CSP (§6).
4. **Смена «характера»:** радиусы (§3.6), тени (0.5px-контур), атмосфера (§5),
   переходы. Всё — токены/одна точка в base.
5. **Смена геометрии:** высоты контролов (`--h-*`), ширины (`§7`), брейкпоинты
   — осознанно, они размазаны по layout/components.
6. **Компонентная переработка:** секция за секцией в `components.css` (§8),
   после каждой — `audit_frontend.py` (0/0/0) и визуальный прогон.
7. **Страницы:** по карте §11, экран за экраном.
8. **Не забыть:** float-окно (те же стили, отдельное окно 380×460), manager-app
   (§17 — только если он в скоупе), печать (§7.4), reduced-motion (§12),
   обе темы **и режим system** (он рендерит третий набор значений).
9. **Финальные ворота:** `python scripts/audit_frontend.py` → 0 критичных;
   `npm run lint` → 0 ошибок; `npx vitest run`; скриншоты «после» —
   сравнить с «до» по всем страницам в обеих темах.
