# ТЗ: какой функционал нужен от API HouseCargo

**Статус:** для отправки разработчикам HouseCargo.
**Контекст:** HouseCargo — готовый продукт со своей логикой и интерфейсом.
Вся автоматика (подбор курьеров, создание посылок, учёт, аналитика) —
на **нашей** стороне, в нашем приложении. От HouseCargo нужен только API,
который отдаёт данные и принимает операции. Ниже — **какой функционал
нужен**, а не как его реализовать: конкретные endpoint'ы, названия полей и
формат — на усмотрение их команды, нам достаточно документации по итогу.

---

## 1. Курьеры

| #   | Функционал                                                                                                                                                                                                                                                                                        | Приоритет  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| 1.1 | **Список наших курьеров** — курьеры, закреплённые за нашим аккаунтом, с полными данными: id, имя, адрес (улица, город, штат, zip, страна), пол, статус, дата истечения, счётчики посылок (новые/отправленные/...), публичное описание                                                             | минимум    |
| 1.2 | **Список доступных курьеров** — курьеры, которых можно взять себе. Имена и адреса можно не отдавать (достаточно id, страна/город/штат/zip, статус, счётчики, описание)                                                                                                                            | минимум    |
| 1.3 | **Добавить курьера к себе** по id. В ответ — полные данные курьера. При достижении лимита — ошибка с указанием лимита                                                                                                                                                                             | минимум    |
| 1.4 | **Авто-назначение при создании посылки** — если посылка создаётся на курьера из списка доступных, панель сама закрепляет его за нами в рамках того же действия (одно действие вместо «добавить курьера» + «создать посылку»). Наша автоматика сама выбирает курьера — этот пункт для нас ключевой | важно      |
| 1.5 | Фильтры списка доступных по стране/городу/штату/zip                                                                                                                                                                                                                                               | желательно |
| 1.6 | Снять курьера со своего аккаунта (обратная операция к 1.3)                                                                                                                                                                                                                                        | желательно |
| 1.7 | Возможность увидеть архивных курьеров (флаг в списке 1.1)                                                                                                                                                                                                                                         | желательно |

## 2. Посылки

| #   | Функционал                                                                                                                                                                                                                              | Приоритет  |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| 2.1 | **Список наших посылок**: id, курьер, название, статус, получатель, вес, количество, магазин, цена, дата доставки, схема оплаты, самовывоз, ASIN/UPC, дата создания, трек-номера (номер + перевозчик), комментарии (текст, автор, дата) | минимум    |
| 2.2 | **Полная история**: постраничная выборка или фильтры (по курьеру, статусу, периоду) — чтобы были доступны посылки за любой период, а не только последние N                                                                              | важно      |
| 2.3 | **Получить одну посылку** по id и/или найти по трек-номеру                                                                                                                                                                              | важно      |
| 2.4 | **Этикетки посылки**: файлы этикеток (base64 или ссылка на скачивание) с указанием трека, перевозчика и формата файла (pdf/zpl/png)                                                                                                     | минимум    |
| 2.5 | **Создание посылки**: курьер, магазин, название, комментарий для admin/support, получатель, вес, количество, цена, дата доставки, схема оплаты, самовывоз (адрес), ASIN/UPC, трек-номера. В ответ — id созданной посылки                | минимум    |
| 2.6 | **Защита от дублей**: внешний id (external_id) или ключ идемпотентности при создании — повтор с тем же значением возвращает уже созданную посылку, а не создаёт вторую                                                                  | важно      |
| 2.7 | Редактирование посылки (треки, дата доставки, комментарий), отмена посылки                                                                                                                                                              | желательно |
| 2.8 | Добавление комментария к уже созданной посылке                                                                                                                                                                                          | желательно |

## 3. Справочники и аккаунт

| #   | Функционал                                                                                                                       | Приоритет  |
| --- | -------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| 3.1 | **Список схем оплаты** (pay_option), доступных нашему аккаунту — чтобы не хардкодить на клиенте                                  | минимум    |
| 3.2 | **Полный перечень статусов** посылок и курьеров + допустимые переходы (документом или методом)                                   | минимум    |
| 3.3 | Информация по ключу: аккаунт, лимит курьеров, сколько занято                                                                     | желательно |
| 3.4 | **Баланс/выплаты**: баланс аккаунта, история начислений, суммы по посылкам (раз есть цены и схемы оплаты — где-то это считается) | желательно |
| 3.5 | **Справочники магазинов и перевозчиков** — допустимые значения полей shop/carrier                                                | желательно |
| 3.6 | **История посылки**: лог смены статусов с датами                                                                                 | желательно |

## 4. События

| #   | Функционал                                                                                                                            | Приоритет  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| 4.1 | **Вебхуки** на наш URL: смена статуса посылки, новый комментарий, новая этикетка, курьер добавлен/снят — вместо периодических опросов | желательно |

## 5. Общие требования к API

- HTTPS, ответы в JSON
- Аутентификация ключом на аккаунт (заголовок или параметр — на ваш выбор)
- Понятные ошибки: код/сообщение + корректный HTTP-статус
- **Тестовый режим**: песочница, тестовый ключ или тестовая схема оплаты —
  чтобы проверить создание посылок и добавление курьеров без боевых данных
- Версионирование и уведомления об изменениях схем заранее
- Если есть рейт-лимиты — документировать

## 6. Что просим в ответ

1. Документацию по итоговому API (методы + примеры запрос/ответ)
2. Тестовый ключ и тестовый режим
3. Список статусов и схем оплаты
4. Рейт-лимиты, если есть

## Минимум первого этапа

Чтобы интеграция заработала в базовом виде, достаточно:
**1.1, 1.2, 1.3** (курьеры), **2.1, 2.4, 2.5** (посылки и этикетки),
**3.1, 3.2** (справочники, можно текстом).
Пункты 1.4 (авто-назначение), 2.2, 2.3, 2.6 — следующим этапом, но именно
они определяют, насколько полноценной будет автоматика.
