# Настройка адреса сервера

**Обновлено:** 2026-08-07

## Проблема, которую это решает

Адрес sync-сервера был вшит в код **семи раз в пяти файлах**:

| Файл                 | Что было                            |
| -------------------- | ----------------------------------- |
| `license.rs`         | `ACTIVATE_URL`, `VERIFY_URL`        |
| `sync.rs`            | `SERVER_URL` (8 обращений)          |
| `ws_sync.rs`         | `WS_URL_DEFAULT`                    |
| `main.rs`            | `BASE` в `sync_catalog_from_server` |
| `database/_cards.rs` | два вызова BIN-кеша                 |

Переопределить можно было **только WebSocket** (`VAULTBASE_SYNC_WS_URL`).
Активация, верификация лицензии, пуш карт, футпринты, BIN-кеш и синхронизация
каталога были намертво прибиты к домену и требовали пересборки клиента.

При этом деплой-скрипты (`deploy_full.py`, `deploy_ssl.py`) поднимают
**другой хост**, чем тот, в который стучится клиент. Слова `otpmanager` нет ни
в одном исходнике клиента или сервера — только в скриптах и документации.

## Как сейчас

Всё сведено в `src-tauri/src/endpoints.rs`.

```bash
# База HTTP-API. Без завершающего слеша.
VAULTBASE_SERVER_URL=https://api.example.com

# Необязательно: полный WS-URL, если он не выводится из базы.
VAULTBASE_SYNC_WS_URL=wss://api.example.com/socket.io/?EIO=4&transport=websocket
```

Если `VAULTBASE_SYNC_WS_URL` не задан, адрес WebSocket выводится из базы
автоматически: `https://` → `wss://`, `http://` → `ws://`, плюс путь
`/socket.io/?EIO=4&transport=websocket`.

Если не задано ничего — берётся прежний адрес по умолчанию, поэтому обновление
клиента без переменных окружения ничего не ломает.

### API модуля

| Функция                          | Возвращает                        |
| -------------------------------- | --------------------------------- |
| `endpoints::server_base()`       | `https://host` без слеша на конце |
| `endpoints::endpoint("/verify")` | `https://host/verify`             |
| `endpoints::ws_url()`            | полный URL socket.io              |

Значения читаются один раз за процесс через `OnceLock`: перечитывать переменные
на каждый вызов незачем, а заодно исключается гонка между потоком WS-цикла и
потоками IMAP-проверки.

## Что осталось решить

Домен по умолчанию (`DEFAULT_SERVER_URL` в `endpoints.rs`) — прежний. Какой
адрес должен стать основным, решает владелец проекта: деплой-скрипты и клиент
всё ещё указывают на разные хосты. Возможные варианты:

1. Поднять `api.`-поддомен на том же хосте, что и остальная инфраструктура, и
   ничего в коде не менять.
2. Сменить `DEFAULT_SERVER_URL` на актуальный домен — тогда правка ровно в одном
   месте, а не в семи.

До этого решения переменная окружения позволяет переключать адрес без пересборки.

## Проверка

```bash
export PATH="/c/msys64/mingw64/bin:$PATH"
cd src-tauri && cargo test --bin vaultbase endpoints
```

Два теста: склейка `endpoint()` не даёт двойных слешей и работает как с ведущим
слешем, так и без него; `ws_url()` всегда отдаёт `ws://` или `wss://` с путём
`/socket.io/`.

Убедиться, что вшитых адресов больше нет:

```bash
grep -rn "eulivehub" src-tauri/src/ --include=*.rs | grep -v endpoints.rs
# должно быть пусто
```
