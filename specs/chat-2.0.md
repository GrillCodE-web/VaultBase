# Chat 2.0 — мессенджер: квитанции, присутствие, контакты, группы

Цель: довести E2E-чат (REDESIGN-05-5B4) до полноценного мессенджера — статусы доставки/прочтения, присутствие, адресные Chat-ID, свои группы, комфортные фичи.

Готово, когда:
- Исходящее сообщение показывает sent -> delivered -> read (галочки), у собеседника приходит read receipt; в группе «прочитали N/M».
- Бейдж непрочитанных обновляется по событию (без 30-сек поллинга), при неактивном окне приходит системное уведомление.
- Видно online/last_seen пиров; у каждого публичный Chat-ID (хеш), label редактируется (свой серверно, чужой — локальная заметка).
- Создаются пользовательские групповые комнаты с выбором участников; менеджер видит и пишет всем.
- Работают: reply (цитата), edit, hard-delete (удаляется у всех участников и с сервера), оффлайн-очередь, @упоминания, черновики, forward, вложения, слеш-команды с приватными карточками ордеров, «важное», пины/реакции/mute/экспорт, бейдж в трее, разделитель «новые», канал-рассылка (туда переезжают manager news), автоудаление по TTL, закреплённые комнаты.

Границы (НЕ входит): поиск по переписке, тихие часы, голос/звонки, federation между лицензиями, SAS-верификация ключей.

Не трогать: транспорт sealed-конвертов (X25519/AES-GCM) и opaque-relay сервера — расширяем envelope v1 полями/типами, совместимость не ломаем. Локальный plaintext в SQLCipher — норма.

Приватность: карточки сущностей (order/profile) едут только внутри sealed-конверта комнаты; сервер видит шифртекст и метаданные маршрутизации. Hard-delete = стереть локально у всех + на сервере.

Риски: локальная cargo-сборка менеджера сломана (openssl-sys/perl) — гейт на CI (build-manager-release); серверные изменения (cc-sync-server) требуют миграций и деплоя; объём ~25 задач, этапы независимы.
