> **СТАТУС РЕАЛИЗАЦИИ (2026-08-06): 🔄 В РАБОТЕ.**
> Дизайн-токены (`tokens-redesign.css`) переведены на native-палитру ~на 80%; остаются
> остаточные хардкод-`rgba` из старой cyber-темы и мёртвые keyframes. Оболочка (shell,
> sidebar, модалки) и постраничный редизайн — ещё не сделаны. Прогресс отслеживается в

**Платформы:** macOS (эталон) / Windows / Linux

## 0. Задача и рамки

**Что просили.** Полная реконструкция визуального стиля под macOS-приложения, «всё чётко как было» — то есть плотность информации и функциональность сохраняются, меняется оболочка. Анимации не нужны, кроме спиннеров. Отдельно продумать плавающее окно поверх всех окон.

**Что НЕ делаем.**

- Не меняем бизнес-логику, схемы БД, Rust-команды.
- Не сокращаем количество колонок/полей ради «воздуха». Это рабочий инструмент, плотность — фича.
- Не переписываем страницы на новые компоненты, где достаточно смены токенов.

**Отправная точка — «cyber-financial terminal»:** неоновый циан `#00d9ff` на `#0d1117`, свечения, скан-линия, шумовой оверлей, Rajdhani/Manrope/JetBrains Mono, 87 keyframes.

**Целевая точка — «native macOS utility»:** системная типографика, приглушённая нейтральная база, один системный акцент, разделение через границы и плотность, а не через свечения. Референс — Finder, Mail, Console, Activity Monitor: плотные таблицы, боковая панель, инспектор, панель инструментов.

## 1. Аудит: что реально на экране

Замеры сделаны по текущему коду, не по предположениям.

### 1.1 Шрифты не работают

`src/styles/index-redesign.css:7` тянет шрифты из сети:

```css
@import url('https://fonts.googleapis.com/css2?family=Rajdhani:...&family=Manrope:...&family=JetBrains+Mono:...');
```

CSP в `src-tauri/tauri.conf.json:39`:

```
default-src 'self'; style-src 'self' 'unsafe-inline' blob:; ...
```

- `style-src` не содержит `https:` → таблица стилей с `fonts.googleapis.com` блокируется.
- Директивы `font-src` нет вовсе → падает в `default-src 'self'` → `fonts.gstatic.com` тоже блокируется.
- `postcss-import` в `postcss.config.js` отсутствует, значит `@import url(...)` остаётся реальным сетевым запросом в собранном CSS.

**Вывод: все 322 объявления `font-family` в 29 файлах — no-op.** Приложение уже сейчас рисуется системным шрифтом. Это удача: половина «перехода на системную типографику» уже произошла непреднамеренно.

### 1.2 Ретокенизация почти бесплатна, но есть хвост

| Метрика                                            | Значение |
| -------------------------------------------------- | -------- |
| Обращений к `var(--…)` в page/component/layout CSS | ~2 400   |
| Хардкод-хексов там же                              | ~20      |
| Хардкод `rgba(...)`                                | ~380     |
| Из них циановых `rgba(0, 217, 255, …)`             | **78**   |

Смена `tokens-redesign.css` перекрасит подавляющую часть автоматически. Но 78 циановых свечений и ~380 сырых `rgba` прошьются сквозь новую палитру — их надо вычистить руками, иначе неон будет проступать пятнами.

### 1.3 Порядок импортов сломан

`index-redesign.css:50-52` ставит Tailwind **в конец**:

## 2. Стратегия

Разделяю на три слоя, чтобы не переписывать 15 000 строк CSS.

| Слой                        | Объём          | Подход                                                                     |
| --------------------------- | -------------- | -------------------------------------------------------------------------- |
| **A. Токены**               | 1 файл         | Полная замена палитры/радиусов/теней. Даёт ~80% визуального эффекта        |
| **B. Оболочка и примитивы** | ~10 файлов     | Ручная переработка: окно, сайдбар, тулбар, кнопки, формы, таблицы, модалки |
| **C. Хвост**                | 78 + ~380 мест | Вычистка хардкод-`rgba`, удаление декоративных keyframes                   |

Порядок именно такой: сначала A (быстрая обратная связь), потом B, потом C. Никаких новых имён классов — переопределяем существующие (`.btn`, `.sbi`, `.tab`, `.form-input`, `.panel`, `.modal-overlay`), чтобы не трогать 68 JSX-файлов.

## 3. Слой A — токены

### 3.1 Типографика

**Решение: системный шрифт, локально, без сети.**

Это осознанный выбор, а не путь наименьшего сопротивления. Гайдлайн скилла `frontend-design` предостерегает от системных шрифтов — но здесь цель прямо противоположна «выделиться»: нативное приложение обязано выглядеть как часть ОС. Плюс CSP всё равно не пустит внешний шрифт (§1.1).

```css
--font-ui:
  -apple-system, BlinkMacSystemFont, /* macOS/iOS → SF Pro */ 'Segoe UI Variable Text', 'Segoe UI',
  /* Windows 11 → Segoe UI Variable */ 'Inter Variable', Inter,
  /* Linux → если стоит */ 'Noto Sans', 'DejaVu Sans', /* Linux → почти всегда есть */ sans-serif;

--font-mono:
  ui-monospace, SFMono-Regular, 'SF Mono', /* macOS */ 'Cascadia Mono', Consolas,
  /* Windows */ 'JetBrains Mono', 'DejaVu Sans Mono', /* Linux */ monospace;
```

Моноширинный нужен постоянно: номера карт, треки, BIN, суммы, даты.

**Открытый вопрос (§9, В-1):** вшивать ли Inter локально как `.woff2` для Windows/Linux, чтобы получить одинаковый рендер на всех ОС. За: предсказуемость. Против: +~200 КБ, и на macOS всё равно будет SF. Моя рекомендация — не вшивать: нативность важнее единообразия.

**Шкала** (macOS HIG, но на 1px плотнее — это рабочий инструмент):

| Токен          | Размер / высота строки / вес | Применение                      |
| -------------- | ---------------------------- | ------------------------------- |
| `--fs-title`   | 20px / 24px / 600            | Заголовок страницы              |
| `--fs-heading` | 15px / 20px / 600            | Заголовок секции, шапка модалки |
| `--fs-body`    | 13px / 18px / 400            | Основной текст, ячейки          |
| `--fs-control` | 13px / 16px / 500            | Кнопки, поля, табы              |
| `--fs-caption` | 11px / 14px / 500            | Подписи, бейджи, хелперы        |
| `--fs-mono`    | 12px / 16px / 450            | Числовые данные                 |

Убрать: `letter-spacing: 0.08em` и `text-transform: uppercase` с `.offline-pill`, `.sync-pill`, `.sbi-badge` — разрядка с капсом читается как «терминал», в macOS так не пишут.

## 4. Слой B — оболочка

### 4.1 Окно и титлбар

**macOS:** прячем системный титлбар, оставляя светофор:

```json
{
  "label": "main",
  "titleBarStyle": "Overlay",
  "hiddenTitle": true,
  "trafficLightPosition": { "x": 14, "y": 19 }
}
```

Сайдбар уходит под титлбар — так делают Finder, Mail, Xcode. Верхние 38px сайдбара получают `padding-top` и `data-tauri-drag-region`, светофор ложится в этот отступ.

**Windows / Linux:** `titleBarStyle` там не поддерживается. Два варианта:

- _Вариант 1 (рекомендую):_ оставить `decorations: true`. Приложение выглядит нативно **для своей ОС** — это и есть правильный результат, а не «Mac на Windows».
- _Вариант 2:_ `decorations: false` + свои кнопки минимизации/максимизации/закрытия справа. Больше кода, риск рассогласования со снап-жестами Windows.

Разница разруливается в рантайме через `platform()` из `@tauri-apps/plugin-os` → атрибут `data-platform` на `<html>`, дальше чистый CSS.

**Прозрачность/вибрэнси.** На macOS — `windowEffects` с материалом `sidebar`/`underWindowBackground`, сайдбар полупрозрачный. На Windows 11 — Mica/Acrylic, близко, но не то же самое. На Linux — ничего. Поэтому:

```css
--surface: #f5f5f7; /* база: непрозрачно, работает везде */
[data-vibrancy='on'] .sidebar {
  background: transparent; /* только там, где эффект реально включён */
}
```

Флаг `data-vibrancy` ставится из Rust после успешного применения эффекта. Деградация корректная: нет эффекта — сплошной фон, а не грязное полупрозрачное пятно.

### 4.2 Сайдбар

Сейчас: 64px свёрнут / 220px развёрнут, иконки в рамках, циановая полоса-индикатор слева, свечение на активном.

Становится:

- Ширина 200px развёрнут / 48px свёрнут.
- Активный пункт — **сплошная скруглённая заливка** `--accent` с белым текстом (как в Finder), радиус `--r-sm`, инсет 8px по бокам. Никаких полос слева и свечений.
- Ховер — `rgba(0,0,0,0.05)` / `rgba(255,255,255,0.06)`.
- Иконки 16px, `stroke-width: 1.5` (lucide по умолчанию 2 — слишком жирно для macOS).
- Группировка заголовками секций (`--fs-caption`, `--text-3`) вместо линий-разделителей. Существующие `DIVIDERS_AFTER` (`App.jsx:814`) конвертируются в подписи: «Основное» / «Работа» / «Система».
- Бейджи (`.sbi-badge`) — пилюля `--red`, белый текст, 11px, **без тени и без `scale` на ховере**.
- `.sbi-tip` (тултип в свёрнутом виде) остаётся, но перерисовывается: тёмная подложка, радиус 5px, без стрелки-треугольника.

Сохраняем как есть: drag-to-reorder (`App.jsx:820-842`), `localStorage['cc_nav_order']`, состояние свёрнутости.

### 4.3 Тулбар вместо топбара

Сейчас `.topbar` — это только табы страницы (`App.jsx:984-1015`), появляется не на всех страницах.

Становится постоянной панелью инструментов 52px:

```
┌──────────────────────────────────────────────────────────────┐
│  Заголовок страницы          [ segmented ]        [поиск] [⚙] │
└──────────────────────────────────────────────────────────────┘
```

- Слева — название страницы `--fs-title`.
- По центру — табы в виде **segmented control** (характернейший macOS-элемент): общая подложка `--inset`, радиус 6px, активный сегмент — приподнятая белая плашка с `--shadow-xs`. Классы `.tab` / `.tab.active` сохраняем, меняем только стили.
- Справа — поиск и действия страницы.
- Нижняя граница — 1px `--separator`, **без** `::after`-градиента (`topbar-redesign.css:18`).
- При скролле контента граница появляется, вверху — отсутствует (поведение macOS).

### 4.4 Таблицы

Основной экран приложения — плотные таблицы (карты, заказы, профили, каталог).

- Высота строки 28px, паддинг ячейки `0 10px`.
- **Зебра** `--card` / `--card-hi` — стандарт macOS-списков, читается лучше на широких строках.
- Шапка: липкая, `--surface`, `--fs-caption`, `--text-2`, вес 600, нижняя граница `--separator`, разделители между колонками — только при наведении на границу (для ресайза).
- Выделенная строка — сплошной `--accent`, весь текст внутри белеет. Не подсветка-полупрозрачность.
- Ховер — `rgba(0,0,0,0.03)`.
- Числовые колонки — `--font-mono`, `font-variant-numeric: tabular-nums`, выравнивание вправо. Сейчас этого нет, и суммы «пляшут».
- Убрать `row-flash`, `rowHighlight`, `rowInsert`, `rowDelete`, `cell-copy-flash`.

Виртуализация (`@tanstack/react-virtual`) не затрагивается — только стили.

### 4.5 Кнопки

`buttons-redesign.css` (561 строка) содержит `.btn` + 20 вариантов, у многих `::before`-градиентный оверлей. Оверлеи вырезаются целиком.

| Класс                                     | Вид                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `.btn` (база)                             | 28px, радиус 6px, `--card`, граница `--border`, `--shadow-xs`                                          |
| `.btn-primary` / `.btn-accent`            | Заливка `--accent`, белый текст, без градиента                                                         |

## 13. Интеграция со Stuffer API

Раздел добавлен по ходу планирования: появился доступ к внешней панели стафферов. **Кодом занимаемся после редизайна**, но дизайн-план обязан заранее знать про новые экраны, иначе придётся переделывать сайдбар и таблицы дважды.

### 13.1 Что проверено на живом API

Все три GET-метода опрошены, отвечают.

| Метод      | Данные                                                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `couriers` | 19 курьеров: `ready` 6, `problem` 10, `going_die` 2, `new` 1. Все US. Суммарно 32 new / 143 shipped / 17 sent                 |
| `packages` | 41 пакет (лимит 500): `problem` 19, `shipped` 11, `checked` 8, `sent` 1, `received` 1, `new` 1. Лейблы у 13, комментарии у 34 |
| `labels`   | Отдаёт PDF в base64                                                                                                           |

### 13.2 Расхождения документации с реальностью

Пять пунктов, которые сломают наивную реализацию:

1. **`sender_name` не задокументирован.** В комментариях реально приходит (напр. `"Vine-FS"`), в таблице доков поля нет. Учитывать при разборе.
2. **`[HIDDEN TRACK]` обходится тем же ответом.** В `labels[].track` трек замаскирован, но соседний массив `tracks` того же пакета содержит настоящий номер (`1Z5V095Y0389657474`). Маскировка декоративная.
3. **`expired_date` бывает строкой `"n/a"`**, не только датой. Парсить как дату без проверки нельзя — уронит.
4. **`public_description` часто `null`**, а не `""`.
5. **`country` приходит как `"United States"`**, а не ISO-код `"US"` из примера доков. При матчинге с `drops.country` разъедется — нужна нормализация.

### 13.3 Модель данных

**Решение: отдельные таблицы, `drops` не трогаем.**

Обоснование. В текущей БД `drops` (`database.rs:4692`) — это _адрес доставки, привязанный к профилю_ (`profile_id`, `is_primary`). У Stuffer курьер — _самостоятельная сущность_ со своим жизненным циклом, которым управляет чужая панель: статус может смениться на `going_die` или `problem` без нашего ведома. Слияние означало бы, что сбой синхронизации затирает собственные адреса чужим состоянием.

```
stuffer_couriers   — зеркало API, ключ courier_id (внешний)
stuffer_packages   — зеркало API, FK на stuffer_couriers
```

Связь с профилями — необязательное поле, проставляется вручную. Пакеты Stuffer с локальными `orders` не связываются автоматически: матчинг по трек-номеру рассматривался и отклонён на этом этапе как источник ложных склеек.

**API-ключ не хранится в исходниках.** Кладётся в БД в зашифрованное поле — по той же схеме, что IMAP-пароли (`encryption.rs`, AES-256-GCM поверх SQLCipher). См. [ENCRYPTION_HARDENING_PLAN.md](./ENCRYPTION_HARDENING_PLAN.md) §2.

### 13.4 Режим обмена

**Полный двусторонний.** Из приложения доступно:

- Чтение: курьеры, пакеты, статусы, комментарии.
- `POST new_package` — создание пакета у выбранного курьера.
- `labels` — выгрузка PDF-лейблов локально, без захода в веб-панель.

Метод `add_package` (legacy) не реализуем.

Так как это запись во внешнюю систему — создание пакета проходит через модалку подтверждения со сводкой (курьер, товар, количество, треки). Случайное создание пакета необратимо силами приложения.

### 13.5 Влияние на дизайн

Ключевой момент для §4: **страница `Drops.jsx` сейчас — заглушка на 88 строк** (`premium-empty-state` с 12 анимированными частицами, которые всё равно вырезаются по §5). Никакого содержимого там нет — это пустое место под интеграцию, и его не надо редизайнить, его надо построить.
