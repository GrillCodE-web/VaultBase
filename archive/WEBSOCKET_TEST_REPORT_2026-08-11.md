## Детальный анализ тестов

### Архитектура WebSocket синхронизации

Согласно документации проекта в `/ws-sync.rs`:

```rust
pub enum WsCredentials {
    pub token:    Option<String>,    // Токен лицензии
    pub group_id: Option<String>,    // ID группы синхронизации
}
```

**Сценарии:**

1. **Solo режим** - пользователь без группы (только токен)
2. **Group режим** - пользователь в группе (токен + group_id)

### Протокол WebSocket сообщений

Согласно `/cc-sync-server/docs/API.md`:

| Тип              | Направление     | Payload                             |
| ---------------- | --------------- | ----------------------------------- |
| `auth`           | Client → Server | `{ token: string }`                 |
| `auth_ok`        | Server → Client | `{ installation_id, group_id }`     |
| `auth_error`     | Server → Client | `{ error: string }`                 |
| `ping` / `pong`  | Bidirectional   | `{}`                                |
| `full_pull`      | Client → Server | `{}`                                |
| `full_data`      | Server → Client | `{ cards: [...] }`                  |
| `push`           | Client → Server | `{ cards: [...] }`                  |
| `card_update`    | Server → Client | `{ cards, updated_by, updated_at }` |
| `catalog_update` | Server → Client | `{ ... }`                           |
| `error`          | Server → Client | `{ error: string }`                 |

### Особенности реализации

1. **Debouncing full_pull** - Запрос данных отправляется не чаще одного раза в 30 сек
2. **Heartbeat timeout** - Соединение разрывается после 2 потерянных ping (60 сек)
3. **Auto-reconnect** - Автоматическое переподключение каждые 3 сек
4. **Token validation** - Токен обязателен, группа опциональна
